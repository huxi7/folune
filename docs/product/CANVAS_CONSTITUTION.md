# Folune Canvas 产品宪法

> 常驻文档：Canvas 的产品定律，不随实现进度变化
> 适用范围：Canvas 的一切实现、增强与重构

## 1. 本文件与 CLAUDE.md 的分工

本文件回答「要做成什么、为什么、哪些东西不能混在一起」。它不是计划，没有进度，也不记录做到哪一步了。

它与各级 `CLAUDE.md` 不是重复，两者的职责恰好相反：

| | 回答什么 | 何时改 |
| --- | --- | --- |
| 各级 `CLAUDE.md` | 现在是什么 | 代码一变就必须跟着变，否则 GEB 两相失同构 |
| 本文件 | 为什么不能 | 代码变了绝不跟着变；只有产品决策本身改变时才改，且那必须是一次显式的决定 |

这条分界不是洁癖。产品定律一旦写进 `CLAUDE.md`，就继承了「必须准确反映代码现实」的义务——于是当有人写出违反定律的实现时，按 GEB 协议该做的事变成**把定律改掉**。有跟随义务的文件没资格当宪法。

2026-08-29 有一次实证：数据库曾用两个触发器让默认 Canvas 的标题跟随来源笔记，`api/supabase/CLAUDE.md` 忠实地把这个行为记成了契约——它没有错，它的职责就是忠实。能指出实现走偏的只有本文件 4.1 那句「重命名源笔记不应偷偷移动 Canvas」。代码的投影无法审判代码。

因此：本文件与代码冲突时，先假定代码错了，并把这个判断拿到台面上讨论；确认要改的是产品语义，就显式改本文件，再让实现与 GEB 跟上。

[历史阶段清单](../archive/CANVAS_V2_PHASE2_BACKLOG.md) 保存当时的增强方向与取舍，不构成当前需求来源。已完成项与主动放弃项不得自动恢复；重新立项须核对当前实现并确认范围。产品约束仍以本文件为准。

[PAPER_CONSTITUTION.md](PAPER_CONSTITUTION.md) 是与本文件**并列**的另一份宪法，守着写作区那张纸、纸上的命令层级与纸到文件树的归档表达。两份文件共享上表那条分工原则，互不隶属：Canvas 内的定律只写在这里，Paper 内的定律只写在那里，跨两个 Workspace 的事实（例如同一篇笔记既有纸也有卡片）在两边各自陈述与自己相关的那一面，不复制对方的条文。

## 2. 产品定义

Folune Canvas 不是一次性的 AI 结果页，也不是允许任意绘画的通用白板。它是：

> 以笔记为知识节点，由用户和 AI 共同拓展、解释、修剪并长期保存的空间化知识工作台。

Canvas 是一级内容对象，AI 拓展是作用于节点的显式命令。用户进入 Canvas 是进入一个持续存在的空间，不等于授权 AI 修改这个空间。

Canvas 的核心价值不是无限平面本身，而是让用户完成一个闭环：

```text
进入空间
→ 放入或发现笔记
→ 看懂为什么相关
→ 手工补充、连接或移除
→ 返回原文阅读与编辑
→ 下次打开继续从原结构生长
```

## 3. 不可违背的产品原则

1. **同一个真实画布**：创建、空白、AI 加载、拓展完成、自动保存与重开必须由同一画布渲染器、同一份数据和同一套交互承载，不再存在「生成时是假画布、保存后才是真画布」。
2. **名词与动词分离**：进入 Canvas 只负责进入；AI 拓展只在 Canvas 内由用户显式触发。禁止提供「进入并顺便拓展」这种混合主入口。
3. **用户掌握因果**：AI 拓展只在用户选中可拓展节点并执行命令后运行；只读问答只在用户发送问题后运行，来源由输入框明确展示。进入空间或改变选择都不触发模型。
4. **空间记忆优先**：普通拓展只能摆放新节点，绝不擅自移动旧节点。用户手工摆过的位置是事实，只有未来显式的「整理画布」命令才能批量改变。
5. **一个对象一份身份**：同一篇笔记在同一张 Canvas 中只出现一个节点。再次搜索或发现它时定位已有节点或新增关系，不复制第二张卡片。
6. **持久化不等于认定**：自动保存负责保住 Workspace；AI 推荐边被保存，不代表用户已经把它确认成全局知识事实。Canvas 局部关系与正式 `memo_relations` 的确认语义必须分开。
7. **渐进披露**：高频且安全的动作直接出现，复杂、低频或破坏性动作逐层收起。理由必须可发现，但不能永久占据画面最显眼的位置。
8. **先复用再创造**：UI 优先复用现有 Design System、Paper、Dialog、Menu、Toast、Markdown 阅读边界和 Workspace Chrome。React Flow 只提供空间机制，不带入第二套产品视觉。

## 4. 内容对象与文件树

### 4.1 Canvas

- Canvas 与 memo、folder 共用同一棵文件树，以独立图标区分类型，不建立第二套「画布管理区」。
- 从笔记进入时，系统创建或复用这篇笔记的默认 Canvas；根笔记成为第一张节点。
- 从笔记创建的 Canvas 默认放在源笔记所在文件夹。创建后两者相互独立：移动、重命名或删除源笔记不应偷偷移动 Canvas。
- Canvas 的标题只在出生那一刻抄一份源笔记名作为初值（不带系统后缀），此后是它自己的名字：源笔记改名不改它，它改名也不改源笔记，两者都能被自己的名字搜到。血缘由 `origin_node_id` 与画布上那张源笔记卡片表达而不由标题表达；摘掉那张卡片，Canvas 即转为独立画布。这一条曾被实现成两个数据库触发器（跟随 + 锚定只读），与上一条直接冲突，已于 2026-08-29 收走——名字跟随就是「偷偷改 Canvas」。
- 空白 Canvas 通过统一新建入口创建：高频主动作仍是一键新建笔记，画布与文件夹进入同一新建下拉。空白 Canvas 默认放在当前文件夹；没有文件夹上下文时放根目录。
- Canvas 内不直接创建正式笔记。Canvas 内可以添加已有笔记和写自由文字；正式笔记仍在 Editor 中创建与编辑。

### 4.2 笔记节点

- 笔记节点是原笔记在 Canvas 中的投影，不是正文副本，也不是第二个编辑器。
- 静止卡片以固定、可布局的尺寸显示标题和有限真实摘录；长正文限高渐隐，不把整张 816px Paper 等比缩成不可读缩略图。
- 完整正文只在按需读取的只读预览中出现。预览不改变节点尺寸，不推动其他节点，不重算关系线。
- Canvas 不持有活的正文编辑器。用户需要修改时进入原笔记编辑器，正文继续只有一个家。

### 4.3 Canvas 自由文字

- 双击空白处创建本地文字，原地输入；空内容退出时不创建对象。
- 静止时只显示文字；选中时出现细边框与四个角点，可移动、按比例缩放、再次双击编辑、Delete 删除。
- 自由文字随 Canvas 自动保存，不进入文件树和全局笔记搜索，不参与 AI 拓展，也不承担正式笔记或知识节点身份。
- 自由文字只提供写、改、移、缩、删；不增加自由画笔、旋转、颜色、字体面板、便签皮肤或复杂排版工具。

## 5. 进入、新建与退出

### 5.1 从笔记进入

```text
笔记 → 进入 Canvas → 创建或打开默认 Canvas → 根笔记自动选中
```

- 不自动执行 AI 拓展。
- 根节点自动选中，使节点工具条和 AI 拓展入口立即可见；这一步消除多一次确认带来的摩擦，同时保留用户控制边界。
- 不提供并列的「进入 Canvas」与「AI 拓展并进入 Canvas」两个按钮。

### 5.2 新建空白 Canvas

- 新建后直接进入真实 Canvas，不出现保存前的临时空间。
- 首屏用低对比提示表达两个起点：`⌘K` 查找内容、双击空白写文字；提示不得冒充工具栏或空状态大卡。
- 第一篇笔记加入后自动选中，随后可 AI 拓展或手工建立关系。

### 5.3 Workspace Chrome 与 Escape

- 进入 Canvas 默认收起左右 Panel，画布保持完整视口；用户可按需展开文件库和 AI Panel，Panel 的出现不得卸载或重建 Canvas。
- `Esc` 按最内层状态收束：先关闭预览/菜单/连接模式，再取消节点选择；没有局部状态时才恢复画布外壳或执行明确的返回行为。
- 从 Canvas 预览进入「编辑原笔记」属于临时离开。编辑器必须提供清楚的「返回〈Canvas 名称〉」，返回后恢复视口、缩放、选择和 Panel 状态；普通从文件库打开笔记时不制造该返回入口。

## 6. 节点交互与操作层级

笔记节点遵循三态：

1. **静止**：只呈现内容，不常驻动作。
2. **Hover**：预览入口浮现，避免把卡片变成管理后台。
3. **选中**：静止选中与框选使用克制的 Soft Ink 细边，表达当前命令对象；只有按住可搬动卡片或已选组时，外框临时转为动态纸边，松手/取消立即恢复细边。整组搬动的卡片共享反馈，命令按钮、连接与画布平移不触发。动态表达「正在拿着」，静态表达「已选中」（2026-09-20 用户明确确认）。卡片不改变背景、不放大、不上浮；与其直接相关的线可轻微增强，卡片自己的操作行随选择浮现。

一级入口是：

```text
元信息行： [ AI 拓展 ] [ 移除 ]
右下圆角： 连接柄
```

- `AI 拓展`：从当前真实笔记继续发现关系。
- `移除`：只删除这张卡片的 Canvas 投影与相关边，不动原笔记。
- `连接柄`：hover / focus / 选中时与元信息行一同浮现，骑在卡片右下圆角上并允许溢出卡片边界。它是这张卡片建立关系的唯一入口，拖与点两种手势都由它承担（见 10.3）。
- 单击选中，点击空白或 `Esc` 取消；选中后按 `Enter` 打开预览、`⌘E` 拓展、`Delete` 移除。右键菜单镜像这些命令，但不能成为唯一入口。

本节原把 `关联` 列为元信息行的第三个图标，并让它「搜索笔记并连接」。该条已废止，原因不是审美：`关联` 描述的是「建立关系」这个能力，而这个能力的自然手势是从这张卡片拉一根线到另一张卡片，不是打开一个搜索框（理由见 10.2）。能力既然改由连接柄承担，元信息行就不该再留一个说同一件事的图标——留着就是同一能力两个入口，而其中一个还指向错误的心智模型。因此元信息行收敛为两个图标，腾出的位置让给柄。

连接柄允许溢出卡片边界，是与下面「操作住在元信息行里」并列的一处刻意例外，理由有二：它压在圆角上，因此不占用任何正文面积；它在视觉上必须与元信息行的图标是不同物种，否则用户不会想到去「拉」它。它仍随卡片一起缩放，仍不构成脱离对象的浮动工具条。

**操作住在卡片自己的元信息行里，因此跟着卡片一起缩放。** 这是刻意的，不是偷懒：

- 卡片是画布上的一个对象，它的组成部分必须与它同比例。让按钮不缩放就等于把它从卡片里剥出来——缩小时按钮溢出卡片、比例失调，那种脱离对象的浮动工具条才是丑的来源。主流画布产品的对象内控件同样与对象同比例。
- 缩小画布是为了「看全貌」，不是为了「操作某一张」。要动某张卡片，用户自然先放大到看得清。给「看」的状态配上「点得准」的精度，是为一个不存在的场景付成本。
- 操作行常驻 DOM，只改变透明度，因此出现与消失都不改变布局；卡片不会因为被选中而抖动。

本节原写「不随缩放改变尺寸的 Context Toolbar」，并要求把破坏性动作收进「更多」。前者已按上述理由推翻；后者精确化为：`移除` 不动原始数据，因此可以留在一级，但在 Canvas Undo 落地之前它必须给出可撤销的回执，不允许无声即成事实。该阻塞级前置已经解除：普通节点与关系的移除会保留完整快照并给出局部撤销；批量移除与其撤销各自都是单次原子 mutation；解除来源血缘的卡片改为事前确认；原笔记已永久删除的墓碑只给出明确的不可撤销回执。真正破坏原始数据的动作（如删除原笔记）永远不得出现在这一行。

## 7. 预览与原文编辑

- Hover 预览按钮或选中后按 `Enter`，在 Canvas 上方打开一张可滚动的只读 Paper Overlay。
- Canvas 留在后方并保持挂载；关闭预览后回到原视口和节点，不重新读取整张 Canvas，不执行 fit view。
- 预览主要服务阅读，因此入口写「编辑原笔记」而不是含糊的「打开这一篇」。
- Overlay 中不编辑正文，避免产生第二套正文状态、撤销历史、自动保存和冲突协议。

## 8. AI 拓展

### 8.1 触发与加载

- 只有选中的、仍有效的真实笔记节点可以拓展；自由文字、空选择、永久删除节点和不可读节点不得触发模型。
- `⌘E` 是选中节点后的加速器，不是唯一入口。无选择时不发请求，只给出「先选择一篇笔记」的轻提示。同一个键在 Paper 里是「进入这篇笔记的画布」——两个 Workspace 互斥，键位不冲突，语义都是「往前推进一步」。
- 结果数量未知时禁止预先摆出固定数量的卡片 Skeleton。加载反馈只围绕源节点表达搜索正在发生；服务端知道真实数量后再物化相应节点。

### 8.2 增量生长

- 每次拓展以当前选中节点为明确来源，一次可产生多篇相关笔记。
- 新节点在源节点周围做 360° 可用空间检测，并继承该分支已有的生长惯性；排布应避开已有节点和可视控件，但不得为了腾位置移动旧节点。
- AI 找到已在 Canvas 中的笔记时，只新增缺失的关系并聚焦已有节点，不复制卡片。
- 普通拓展只追加，不静默删除旧结果、不洗牌已有结构。再次拓展的可用性由源笔记 revision 与知识库变更共同决定：都未变化时表达「已是最新」，有新内容时只补充新的节点或关系。
- 单张 Canvas 不设节点硬上限。AI 拓展始终从用户明确选中的单个源节点出发，模型上下文只读取那一篇正文，从不读取整张图，因此节点总量不会吞噬模型上下文；读图 payload 与 React Flow 渲染若将来出现真实性能证据，再按证据优化，不用半截的 UI 或数据库阈值截断人工与 AI 路径。

### 8.3 拓展来源与关系图

- AI 新带入的节点拥有一个唯一「首次拓展来源」，用于增量布局和主要推荐理由；根节点与用户独立添加的节点没有首次拓展来源。
- Canvas 长期结构是图而不是严格的树。同一笔记后来可以被另一个节点再次发现，也可以由用户手工连接，因此允许多条关系，但仍只有一个节点实例。
- 首次来源是节点的发现历史，额外边是知识关系；二者不得混成只能一对一的父子模型，也不得靠复制卡片规避多关系。

## 9. 推荐理由

- 理由回答「为什么把这篇笔记带到这里」，是 AI 可解释性的核心，不得删除；它又不能永久压在线中央抢夺阅读层级。
- AI 新节点物化时，简短、具体的主要理由视觉上靠近目标节点出现。稳定状态下通过目标节点的「为什么相关」或关系 hover/选择再次查看。
- 理由的数据归属是具体边，不写进笔记正文；视觉上可以贴近子节点，以符合用户沿拓展路径阅读的直觉。
- 单一首次来源只显示一个主要理由；存在附加关系时按来源分别列出，不因节点选中就自动铺开全部理由。
- 用户手工连线不强迫填写理由。建立后可以补一句关系说明，也可以跳过。
- **理由写在线上这个方案已被实测否决，不要再提。** 一条长到能容纳 148px 理由的连线，会把 1440px 屏上的纸压到 424px——正文约 8px，不再是「仍然可读」；而一块舞台色的标签压在页边上，读起来像纸上被打了个洞。作为卡片外的无框说明，理由不占任何横向预算、始终清晰、永远不是 tooltip，卡片则只留笔记本身：标题加逐字引文。

## 10. 添加、查找与连接

### 10.1 全局 `⌘K`

- `⌘K` / `Ctrl+K` 在任何 Workspace 中都保持纯粹身份：快速查找并打开笔记、Canvas 等内容对象。
- `Enter` 始终打开或切换搜索结果，不能因为当前位于 Canvas 就偷偷改成「添加」。
- 在 Canvas 中，笔记结果额外显示显式 `＋`：点击后把该笔记加入当前 Canvas；已存在时改为定位并选中已有节点。
- 全局搜索与 AI `@` 可复用检索数据源和结果原语，但命令壳、提交语义与可见文案必须各自明确。

### 10.2 添加与建立关系是两件事

- **添加**（把库里的对象放进 Workspace）有三条直接路径：全局 `⌘K` 结果行的显式 `＋`、底部控制区的 `加入笔记`，以及从文件库把 memo 拖入 Canvas。三者语义相同，默认不连线；前两条保证键盘与鼠标用户都能发现，拖入负责已经看见目标时的直接操纵。
- **建立关系**（给已经在画布上的节点增加关系）只有一个入口：卡片的连接柄（见 10.3）。它永远作用于画布上已有的节点，不承担把新对象带进画布的职责。
- 任何路径都不得从卡片的连接入口打开搜索面板。

本节原规定「从选中节点的『关联 → 搜索笔记并连接』进入同一 Note Picker」，并把它与全局 `＋` 并列成添加闭环的两半。该条已废止，理由是它与本文件 10.3 自己的几何直接冲突：既然端点由两张卡片中心的射线求边界交点、根本没有固定端口，那么「从这张卡片拉一根线到那张卡片」就是这套几何天然的输入姿势；在这条链上插一个搜索框，是整条链上唯一不匹配的一环。用户点连接时想的是「那张卡片」，不是「那个词」。

搜索框因此退回它唯一正确的身份：查找与打开（10.1）。它可以把一篇笔记放进画布，但那是「添加」，不是「建立关系」。

### 10.3 手工连线

用户可以连接 Canvas 中已有的笔记节点，这是基础能力，不属于后续复杂白板功能。

**几何决定了柄的数量**

- 连线逻辑上连接节点中心，视觉端点取中心射线与卡片边框的交点；节点移动到任意方向后，线都自动落到自然边缘，不使用固定在单侧的永久端口。
- 因此柄与端点是解耦的：**柄是抓手，不是端口。** 柄的位置只服从「最不干扰」，不承担任何方向暗示，也因此不需要四个。这条几何就是「一个柄」而不是「四边端口」的全部依据——四边端口只在柄本身就是端点的产品里才是必需的，把那种布局照搬过来会同时遮住正文并暗示一个不存在的固定出线口。

**两条路径，缺一不可**

- **拖拽是主路径**：按住连接柄拉出临时线，落在目标卡片的任意位置松手即连上。合法目标以 1px Soft Ink 细边与极淡外环表达可落，不移动、不缩放、不改变背景。
- **点击是等效路径**：点击同一颗柄进入连接模式，再点另一张卡片完成连接；合法目标同样高亮，`Esc` 取消。
- 点击路径不是冗余。它是 WCAG 2.5.7 Dragging Movements（AA）的硬要求：任何以拖拽完成的功能必须提供单指针等效路径。**它不得以「简化交互」为由被移除。**
- 自连、已存在的重复关系、无效或墓碑节点必须给出明确的无效反馈，而不是静默失败。
- 全程不打开 Command Palette。

**两种线，形态不同是刻意的**

- **拖拽中的临时线**表达「手势正在发生」：多股编织、沿路径正弦摆动、波幅随绳的松弛程度变化（拉近则波大、拉远则收细绷直），线头带游标。它的坐标严格跟随指针，不加任何弹簧延迟——摆动是形态，不是坐标的粘滞；把它做成坐标延迟会毁掉直接操纵的手感。
- **它是弹簧，不是麻绳**：圈数恒定，拉长只是把同样这几圈抻开抻平，因此「卷着」与「被拉直」是同一根东西的两个状态——这正是那份张力的来源。反过来把波长钉死、拉长就多长几圈，是麻绳：越拉越松、越拉越弯，与手上越拉越紧的体感相反。给圈数设上下限更糟：它会在某个距离上从「多长几圈」切换成「波长变长」，同一次拖拽里出现两种行为，读起来是割裂的。拉远仍看得见波浪靠的是波幅有下限，不是靠多长几圈。`[决策: 所有者 · 2026-09-02]`
- **波沿着绳往前跑**：时间进到波这一项，因此绳身上的起伏是行进的，而不是钉在绳上、只让三股彼此互绕。曾经反过来试过——把波钉住、只留互绕——那一版没有被接受。摆动的能量只许来自波与股距这两项：尾端扇开与相位无关，不参与摆动；任何第三个带相位的项都是在给这根绳加它不该有的抖。`[决策: 所有者 · 2026-09-05]`
- **松手后的关系线**表达「关系已确立」：恒定细描边、两端以透明度收细、静态。它就是既有的那根关系线，不继承临时线的任何物理特征。
- 这个差异不是省事：关系线是复数，一张画布上可能几十条同时存在；若它们的宽度随距离变化，每拖动一张卡片整张图都会跟着呼吸。临时线永远只有一根、只活在一次手势里，所以它付得起物理感的成本。
- 临时线是纯瞬态对象：不进 WAL、不进关系模型、不参与保存，松手即销毁；正式线的出现沿用既有的画线回执，不另造过渡。

文件库拖入是正式的直接操纵路径，与本节的柄并行而不替代它：柄解决「画布上已有的两张卡片之间」，文件库拖入解决「把库里的对象带进画布」，后者属于 10.2 的添加语义且默认不建立关系。

## 11. Canvas 导航与控制

### 11.1 常驻控制

底部中央保留克制的 Canvas Controls：

```text
[ 加入笔记图标 ]        [ 适配视图 ] [ 缩小 ] [ 放大 ] [ 操作说明 ]
   内容动作                        视口动作
```

（本节原写「右上角」。Canvas 顶层收敛成四块分区后右上角归 AI 开关，命令条下移到底部中央；这是产品决策的更正，不是实现走偏。顺序未变。）

- `加入笔记` 与其余四项**不属于同一类**：它把对象放进 Workspace，其余四项只改变观察方式。两者因此分属两个独立容器、以留白分隔，不得用分隔线包成一组——分隔线表达「同一个东西的两个部分」，留白表达「两个东西」。把内容动作和视口动作并进一条，是把名词与动词又混回去。
- `加入笔记` 不得被删除。它是 `⌘K` 的可发现性代理：`⌘K` 对只用鼠标的用户是零可发现性，删掉它，第一次进入空 Canvas 的人就没有任何可见的添加入口。2026-09-02 经产品复核后收敛为稳定的 `FilePlus` 图标入口；可访问名称与 tooltip 必须明确写「加入笔记」，不能退回裸 `Plus`，也不能让它被误读成缩放或连接。
- `加入笔记` 与视口工具使用同一套中性 Ghost 控件材质；语义差异只由独立容器、留白和 `FilePlus` 字形表达，不再用常驻 Tonal 底色制造第二焦点。它不得因为 Canvas 从空变为已有节点而改变材质，也不得按节点数量在 Primary/Tonal/Ghost 之间切换；空画布的首次引导由空状态文案承担。

- `适配视图` 是迷失恢复的基础能力，优先于 MiniMap；只在用户显式触发时平滑包住全部内容。
- 缩小和放大是触控板/滚轮以外的可发现入口。
- 操作说明用轻量 Popover 陈列选择、框选、移动节点、移动画布、缩放、预览、AI 拓展、添加文字等快捷方式，不做首次强制教程。
- 左键拖空白用于框选；中键或 Space + 拖动用于平移画布；滚轮/触控板负责缩放。具体键位必须在操作说明中可发现，并尊重 reduced-motion 与键盘可访问性。

### 11.2 控制层级

- 底部中央：全局 Canvas Controls。
- 左上：文件库开关与画布标题；右上：AI 开关；右下：保存状态。四块分区共用同一组 inset/top 变量，不许各自算位置。
- 节点附近：只作用于选中对象的 Context Toolbar。

## 12. 自动保存、恢复与删除

- Canvas 从创建开始就是持久对象，不存在用户必须点击的「保存为画布」。
- 节点、自由文字、关系、坐标、视口及必要的 Workspace 状态先本地即时生效，再在用户停手后合并安静回写；不得每一帧请求，也不得用保存失败阻断拖动和阅读。
- 导航离开、页面隐藏及重要上下文切换前必须 flush 必要变更。长时间失败才进入可见反馈，短暂失败有界重试。
- 重开必须恢复同一内容、位置、视口和关系；程序性 fit view 不得伪装成用户视口写回。
- 从 Canvas 移除笔记节点只删除其 Canvas 投影和相关边，不删除原笔记。
- 原笔记软删除时保留节点并标记「在回收站」；永久删除后保留足以解释空间位置的标题/摘录快照和墓碑，用户决定是否移除，不自动塌缩布局。

## 13. 产品边界

三类东西必须分清：**决定不做**、**不承诺做**、**已确认待办**。把第二类当成第一类会错杀方向，把第一类当成第三类会让 Canvas 滑成通用白板。

**决定不做**——它们与第 2 节的产品身份直接冲突，想加就先改第 2 节和这一节：

- 自由画笔、几何形状、图片、Frame、Group、旋转等通用白板工具。Canvas 的平面服务于知识关系，不服务于作图。

两条从写作区继承来的边界，必须记在这里才不会被反向侵蚀：

- **「无纹理、无点阵、非白板」这条禁令只约束写作舞台。** Canvas 是另一种空间语境，允许平移缩放与极淡点阵。但这个例外**绝不许泄回写作区**——写作区一旦长出点阵，纸就不再是纸。
- **Stage 与 Canvas 是两个名词，不许混用。** 工作区背景叫 Stage（`--workspace-stage`、`.workspace-stage-control`、`data-mode="stage"`、`handleStagePointerDown`），名词 Canvas 只留给这张知识画布。把背景重新叫回 canvas，产品里就会有两个 Canvas，之后每一次沟通都要先消歧。`.note-editor-canvas`、Color Lab 的类名与 `canvas-confetti` 各有无关含义，不在此列。
- MiniMap。`适配视图` 已经承担迷失恢复，真实使用没有证明需要第二套空间导航；「大画布也许会迷失」是假设，不是证据。本条与同源的「大规模节点性能专项」一同被裁决，出现可复现证据时按具体瓶颈重新立项。

**不承诺做**——没有被禁止，但不在任何排期里，需要独立验证用户价值后单独立项：

- 跨多张画布的全局 AI 问答；
- Canvas 内创建正式笔记，或把自由文字晋升为笔记；
- 多人实时协作、离线同步与多页面 Canvas；
- 后台自动持续探索。

**已确认待办**——只增强已经成立的 Workspace，不改变本文件任何核心语义。[历史阶段清单](../archive/CANVAS_V2_PHASE2_BACKLOG.md) 记录了当时的方向，不代表当前待办状态；重新立项须核对当前实现并确认范围。MiniMap 仍属「决定不做」。

## 14. 宪法级验收问题

任何实现方案都必须能清楚回答「是」：

- 用户第一次进入和重新打开看到的是不是同一张画布？
- 用户没有选中笔记时，AI 是否绝不会运行？
- 普通 AI 拓展是否只增加新内容而不搬动旧节点？
- 同一篇笔记是否始终只有一个 Canvas 节点？
- 每一张 Canvas 是否都能被用户亲手命名，并被自己的名字搜到？
- 用户是否能看懂每条 AI 推荐为什么出现，又不会被理由永久淹没？
- 用户是否能添加、连接、移除笔记并写下不进入文件树的想法？
- 卡片上建立关系的入口，是否绝不打开搜索面板？
- 任何用拖拽完成的连接，是否都有一条等效的单指针路径？
- 用户是否无需点击保存就能在刷新后恢复原状？
- 用户从 Canvas 进入原文编辑后，是否能回到原视口继续工作？
- 删除原笔记是否保留可理解、可处理的 Canvas 空间痕迹？
- 产品是否仍是结构化知识 Canvas，而没有滑向通用白板和第二套笔记编辑器？

## 15. 画布只读问答

2026-10-07 明确决策：当前画布和 @画布进入同一 Folune AI。
问答只阅读与解释，不修改笔记或画布。
输入框提供整张画布和指定笔记两种范围。

画布手势选择不自动替换问答来源。
