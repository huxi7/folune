# app/
> L1 | 父级: ../CLAUDE.md

用户端模块，负责承载浏览器内的 Folune 产品体验边界；内部技术标识保留 SuperNote。

技术栈: Bun + Vite + React 19 + React Router + Zustand + Motion for React (`motion/react`) + @xyflow/react 12 + Vercel AI SDK/useChat + @mastra/client-js + canvas-confetti + Kumo UI + Tailwind CSS v4 + 本地 design system + Supabase Auth SDK + system/light/dark 全局主题偏好 + Lucide React + CodeMirror 6/Lezer Markdown GFM + react-markdown/remark-gfm/remark-breaks/rehype-sanitize + TypeScript。

Canvas 已落地为一级持久 Workspace。memo 默认 Canvas 与 standalone Canvas 共用 React Flow 会话、WAL 与单一保存协调器；用户可从命令面板或文件树拖入 memo，预览/编辑原文、创建自由文字、连接/删除/拖拽/缩放并显式 AI 拓展。连接使用卡片底栏行尾抓手的拖/点等效路径（三个入口严格等距），临时弹性绳只活在 UI 且两端只有抓手与指针，并沉在卡片之下与已成立的关系线同层；路由离场先 flush，本地已持久但未同步时允许继续并诚实提示；页面重开、冲突、响应丢失和 pagehide 沿同一恢复协议处理。

备忘录状态约束: `src/shared/store/memoTreeStore.ts` 只保存 active 文件夹/笔记结构与摘要，`memoDocumentStore.ts` 是按 ID 正文与草稿的唯一客户端状态源；目录响应禁止携带 `content_mdx`，用户打开笔记后才读取该 ID 的完整正文并缓存，切换/登出必须中止或门禁旧响应。当前关键词搜索可由 `/memo-search` 在服务端匹配正文，但只回传命中 ID/摘要；未来向量/混合检索不得把正文重新塞回整树。GET 整树只允许在进入 Dashboard、登录用户变化或显式刷新时发生；人工创建必须同步插入临时 Memo、立即进入编辑器且不锁定后续创建，多个提交独立并发，临时/真实 ID 替换不得重挂载编辑器或覆盖等待期间的标题/正文，失败只精确撤销对应节点。重命名、移动、软删除与恢复同样必须乐观更新或合并局部响应，严禁写成功后刷新整棵树。Trash 只保存回收站列表视图状态，不得复制 active tree。删除当前 Memo 或其祖先前必须等待 `useMemoAutosave` required flush，失败保留路由、编辑会话和 subtree；删除成功后暂停旧会话、清理受影响 last-memo/正文缓存并导航到下一 Memo 或 `/app`。“需要 flush”与“需要导航离开”是两件事：画布没有编辑会话，删除正在打开的画布只导航不 flush，不得因为拿不到编辑器而静默失败。中央连续画布、Markdown、reading/live/source、安全渲染与空白保真继续遵循既有单一存储协议；自动保存仍使用既有调度/重试参数且所有保存携带显式 memoId。

命名约束: 重名的最终裁决在数据库唯一索引 `(user_id, parent_id, node_type, memo_title_norm(title))`（排除 deleted_at，根节点单独一条 partial index），前端 `shared/store/memoTitleRules.ts` 只是它的镜像，负责即时反馈。禁止同 user、同 parent、同 node_type、规范化标题相同；一篇笔记与它的默认 Canvas 同名、不同类型对象同名都合法。规范化只在两处各实现一次并保持同语义：首尾空白、连续空白折叠、拉丁大小写。系统生成的默认名（未命名备忘录 / 未命名 Canvas）撞名时由服务端顺位让开为「… 2」，用户亲手输入的名字撞名绝不替他改名，只回 409 `MEMO_TITLE_CONFLICT` 并原位提示。标题与正文是两条独立提交路径：撞名只挂起 title 字段并在标题编辑区原位提示（保持编辑态与用户输入、不发注定失败的标题请求、不静默回滚、也不把这个名字反写进文件树），正文必须继续正常自动保存；确定性冲突不进入退避重试。命名零特例：笔记、默认 Canvas 与 standalone Canvas 共用同一条规则，任何节点都能从文件树的双击/F2/右键三个入口原地改名，也能在画布顶部标题处改名。默认 Canvas 只在出生那一刻抄一份来源笔记名作为初值（不含任何系统后缀），此后归用户，谁也不跟随谁——它承载了笔记里根本不存在的内容（AI 拓展出的节点、连接、自由文字），是笔记的派生产物而非渲染方式，因此必须能被自己的名字找到。血缘由 `canvases.origin_node_id` 与画布上那张 memo_ref 卡片表达，两处都不受改名影响，所以放开命名不丢任何关联信息；摘掉那张卡片画布即自动转为 standalone，这是它取得完全独立的那道门。新建对象若在提交期间被服务端改名，本地以「是否还等于提交值」判定是否接纳，绝不用服务端返回值覆盖用户已开始输入的标题。

备忘录舞台约束: APP 使用纯中性灰 Workspace Stage 衬托唯一常驻 Paper；Light Paper 纯白、Dark Paper 为同一明暗轴上的深纸面，允许极弱边缘、克制圆角与多层柔影。写作态 Stage 禁止纹理、点阵、渐变光斑与任何空间/白板交互——Canvas Workspace 是唯一例外，其视觉不得反向渗透写作态。Paper 与左右 Panel 是三层而非并列（Stage 背景 → 贴在它上面的 Paper → 压在 Paper 上的 Panel），因此 Paper 不参照 Panel 的顶部留白或顶部边界；Paper 开本高度优先且没有宽度上限：短内容的最小开本与 Panel 几何同构，纸高取两条 Panel 内缩线之间的可用高度（桌面 inset 16px），超过这个页高后脱离 Panel 高度约束、只向下生长，顶部不人为设边界（滚动时纸继续向窗口上方延伸），纸宽按 7:9 反算（1280×720≈535×687、1440×900≈675×867、1920×1080≈815×1047），高度由同一 grid area 内一块无内容比例基线给出，因此长文由真实正文把同一条轨道撑长；舞台上下留白正好等于 inset，空/短笔记完全不产生滚动，横向装不下时改以可用宽度为先并放弃底边对齐，窄屏改用可用视口。内部写作列上限 45rem 且不随纸变宽而变长；Paper 顶部 sticky 顶栏钉在 Panel 那条内缩线上（不是浏览器顶边），左侧只放身份（返回来路、归档落点、滚动后淡入的标题），右侧命令区顺序冻结为整理笔记 → 进入 Canvas → 阅读切换 → 更多（12/12/4 留白分组、无竖线），整理是唯一核心动作但材质是 Quiet Accent（静止无背景/边框/外影，hover 才浮出 primary-soft，只有 loading 才凝结成 Processing 实体），Filled Primary 只留给文件库的「新建」；凝结由 scroll timeline 在 24–80px 线性推进唯一那个进度：实底锚在顶栏下沿向上长满「48px 顶栏 + 一条 inset」，下缘 16px Soft Edge 的高度/模糊/遮罩全部乘同一个进度，因此正文靠近顶栏时先变软再被纸吃掉；铺开的是同一个 paper-surface 而不是第二种表面，且**不画任何底边线**——那条线会把「窗口上边 → 线」整段圈成一个随滚动变宽的物体，边界只由软边表达，顶栏**上方**那条留白里永远只有纸、一行字都不露（sticky 停在内缩线上，纸一滚那条带子就成了纸的内部），静止时连一层模糊都没有（标题 36–80px 只淡入、不位移，回顶沿同一路径融回）；24/80 受约束而非手感——正文抵达顶栏下沿是 1px 纸边 + 正文上边距，窄屏只有 33px，不支持的浏览器只用一个哨兵软切一次；文件库/AI 开关位于 Stage。切换 memo 只替换 Paper 内部内容；标题、正文、Panel 动画与 reading/live/source 切换不得破坏 CodeMirror 选区、撤销历史或自动保存会话。

知识画布约束: Canvas 是与 Paper 并列的一级持久 Workspace，树身份固定为 `memo_nodes.id === canvases.node_id`，memo 默认 Canvas 并发进入只能得到同一个 ID，standalone 从创建起也必须是 protocol 2。CanvasWorkspace 保持中央 React Flow 实例不因左右 Panel、Preview 或 Picker 开合而卸载；允许 pan/zoom、点阵、连接、删除、拖拽和自由文字四角等比缩放；键盘加速器为 Enter 预览、Delete 移除、Escape 逐层收束、⌘E 从选中节点 AI 拓展（无选择只提示不发请求），且全部在输入框与自由文字编辑态让路——⌘E 在 Paper 里是「进入画布」，两个 Workspace 互斥所以同键不冲突，空间文字静止时只显示文字，编辑态只有输入光标且无边框，选中才显示四边等距紧贴内容的四角边界。选择只有一个所有者，且那个所有者是 React Flow——指针真正拨动的是 node.selected，canvasWorkspaceStore 的 selectedNodeIds 只是它的镜像；程序化改选择（Esc 取消、加入后定位、连接完成后回到来源）必须经 selectOnly 写进它的节点，只改镜像会让卡片留着描边不动，入口聚焦节点是唯一一次外部写入且每张画布只交一次。两边互为输入会在进入默认 Canvas 的那一刻就逐帧互相纠正并让 React 抛 Maximum update depth exceeded，因此节点几何推导禁止读选择，选择推导禁止写几何。框选反馈参照 Excalidraw/tldraw：被框住那几个元素的外接框从第一张被框住起就在，抓住组里任意卡片拖动时也不许消失（React Flow 自带的 NodesSelection 恰好在这两刻缺席，必须补上并在它画框时让位，同一时刻只允许一个框），松手后继续留在原处；两个框刻意不对称，因为它们说的是两件事：外层框选框是手势、罩的是空地，带一层 --primary 6% 的极淡底，让「这块地算不算我的」一眼成为一整块而不必用眼睛描一圈；内层成组外接框是状态、罩的是卡片与文字，只留线，给它底色等于给内容蒙一层纱——这与 §6.3「选中不改变背景」是同一条。三条线共读同一个 --canvas-selection-line 因此不可能走形；第三方默认的饱和蓝底与蓝虚线由改写 React Flow 自己的 --xy-selection-* 变量换掉，内层在它自己那一层把底改回透明，全程不靠 !important 压它未分层的规则。拖动的坐标回写单位是一次手势而不是一个节点：整组的最终坐标必须整组进入同一条 WAL 记录，抓卡片拖和抓外接框拖走同一条路；少写一个，乐观投影就把它弹回旧坐标，用户看到的是松手那一刻组内相对位置散掉。对象 `text_scale`（0.25–8）与宽高经同一 mutation 持久化，Canvas viewport zoom 只做视觉变换不改对象尺寸，`onlyRenderVisibleElements` 不开。恢复 user_moved 视口前必须先判定它在当前画布尺寸下还看得见节点，否则退回 fitView——视口是按存它时的设备算的，原样搬到更小的窗口会让整幅图落在屏幕外。memo_ref 卡片的元信息状态只表达「指向的东西不在库里了」（墓碑、回收站）——用户必须知道且有出路；禁止再引入既验证不了又消不掉的提示，例如按入画布那天的 revision 快照比出来的「原文已更新」：标题与摘录本来就读最新内容，那个不一致用户看不见，而快照只在创建时写一次，这行字一旦出现就永久留在卡片上。memo_ref 卡片是固定 280x360 的纵向笔记预览纸：卡片只嵌一张共享 NotePaper 连键都不出现；两个画布入口把同一身份补回返回的 tree node，使就地并入目录的节点与整树一致，全局搜索靠它给画布结果行标注来源笔记标题，并让笔记行的 Tab 直达自己的画布。memo_ref 只保存标题/摘要/revision 快照，正文只在用户打开 Preview 时按 memo ID 读取，Preview 是遮罩中央唯一出现的纸：几何是常量、不随正文长度变化，并按 ISO 216 的 1:√2 立成 A4 开本（宽取 40rem／视口高／视口宽三者最紧者，高由比例导出），以 --paper-float-shadow 的渐变柔影悬浮在明亮磨砂遮罩之上；页边固定为纸宽 8%。模态是固定取景框：纸面与纸外工具列在滚动中静止，正文在纸内滚动并复用全局细滚动条。纸内只允许正文，关闭与“编辑原文”一律住在与纸顶右角对齐的纸外 32px 圆形工具列（窄屏 API；禁止组件直写第二条路径。协调器按 600ms 封装、100 操作/48KiB 上限、稳定 mutation_id、单次 409 rebase 和有界重试运行，pagehide 只 best-effort 发送首批且剩余 WAL 必须保留。AI 只在用户显式触发时运行，已有完整 checkpoint 且语料未变直接返回最新；新节点按既有分支向外增量布局，旧节点坐标永不因 AI 重排。Canvas 的全部非圆形表面必须与全站共享同一 squircle 平滑圆角，嵌套的卡片外壳与纸张只允许曲率半径不同、形状语言相同；圆形入口显式退回 round。Canvas 顶层只有四块分区，全部由 --canvas-chrome-inset/top/size/gap 一组变量定位并锚在 canvas-stage 上：左上是文件库开关+安静标题、右上是 AI 开关、底部中央是加入/适配/缩放/说明命令条、右下是保存状态；开关槽位常驻以保证标题横坐标不因面板开合而移动，禁止用零散 top/left 让浮层互相躲避，也不再有伪返回按钮、Canvas 文字标识或包裹整组内容的厚重卡片。Canvas 的浮层间距与顶栏基线不许自成一套：inset 直接取 Paper 那侧的 --workspace-panel-inset，top 复用 .workspace-stage-control 的同一条公式（inset + 1px 边框 + 控件在 48px Header 内居中），因此关闭态的左右开关、画布标题与打开后住进 Panel Header 的收起命令永远落在同一条水平中心线上，开合与断点都不会让这排东西上下错位。标题是画布身份的唯一表达，两种画布都在此原地重命名，零特例；回到来源笔记不由标题承担——那是画布上那张 memo_ref 卡片的职责，它本来就躺在画布原点且是进入时的聚焦节点，标题再挂一个入口只是同一件事说第二遍。拖拽中的临时绳与松手后的关系线必须同层且都在卡片之下：同一个对象不该在松手那一帧从卡片上面掉到下面，而那一帧恰是用户最需要「成了」的时候；线的信息只在两端与走向，卡片里是要读的字，让线盖住字是拿主要换次要；被卡片挡住≠被冻住——线仍严格跟指针、只是钻到纸底下，而"停在卡片边缘"会被读成卡顿，落点感一律由目标卡片自己亮一圈承担。临时绳的波形是 sin θ + sin 3θ（M 与 W 交替、中间转角落在中线），波长恒定而周期数随距离增长，三股速度不同且与由深到淡的透明度同序，末端一颗实心小珠由三股绕过而不是从珠子发射。关系线复用 Cord Signature，理由与删除动作只在 hover/选中出现；文件树以图标区分 Canvas 与 memo，不暴露扩展名。卡片↔预览、预览↔写作区、写作区↔画布四个方向的放大缩小一律交给浏览器原生视图过渡，节奏只在 `styles/knowledge-canvas.css` 声明一次，并受三条不可协商的法则约束：① 一次手势里只有纸壳与纸内正文两个 view-transition-name，别的元素——遮罩、面板、工具列、画布——一律留在 root 的截图里；过渡层的兄弟顺序由被捕获的先后决定，与 z-index 和 DOM 嵌套无关，只在新状态出现的名字排到末尾，因此一层自带名字的全屏遮罩会整段盖住那张正在放大的纸，用户看到的是一片空白然后结果「跳」出来。② 纸壳可以被拉伸（命名后代已被提出它的截图，那张图里没有字），正文永不缩放：两端都按原始尺寸绘制并由取景框裁切，纸长大只是露出更多正文；把字当图片放大就是「字在膨胀」，两端同时膨胀再叠起来就是「突然弹出来」。③ 世界先落定：遮罩与画布是环境的状态改变而不是与纸同行的物体，必须在形变的前小半段换完；留到最后才揭开更糟——用户会盯着一张纸在空无一物的底上缩小，那正是「没有动效」的观感。入场编排只属于第一次进入：返回一张刚离开的画布不得重播节点入场，那张图一直在，重播只会让用户看着一片空白卡片自己填字。一次画布会话的身份只有（登录用户, 这张画布），进入语境与回调都不得作为重建条件：上层记录一次返回描述就重建会话，代价是清空文档与预览、掐断在飞的保存，并让预览在过渡取景之前就消失。reduced-motion 直接呈现静态终态。

知识画布视觉补充: memo_ref 关系必须持续读取两张卡片的真实绝对矩形，以中心连线与各自边界的交点作为可见端点，目标跨象限拖动时端点随之换边，禁止依赖固定左右 Handle 坐标。这里的边界是卡片可见的圆角轮廓而不是尖角矩形——尖角落在圆角削掉的空处，端点会在对角方向露出悬空的一截；端点宁可略微进到卡片底下（边层在卡片之下，看不见），也不许露在外面。任何“把端点夹在边中段”的做法都被禁止：它会先把端点钉住再在越过角时跳掉几十像素，正是这条曲线要消灭的东西。弯度是弦法向上的反对称偏移 bow·sin(2θ)（等价于 2·dx·dy/L²）：水平或垂直对齐时归零成直线，四条对角线最弯且必须是两个弯的 S，其余角度连续过渡——禁止用 Position 枚举、象限判断或任何分段切换实现弯度，因为那会让一张卡片绕另一张转动时每 90° 跳一次。曲线中点常驻低对比查看入口，人工与 AI 来源分别标注；理由的指向面是整条关系线本身，中点标记只是它常驻可见的把手，完整理由必须可由整线 hover、中点 hover、选中、点击保持和键盘聚焦到达，且指针在线与标记之间交接时不得闪断。thumbnail 正文只允许在最后约两行以连续透明度衰减和完全无填色的渐进失焦收尾，禁止不透明覆盖层形成横向色带或提前吞掉仍可展示的摘录。文件库 96px 新建 split 必须与全局控件共享 smooth squircle 形状。
