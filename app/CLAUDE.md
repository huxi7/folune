# app/
> L1 | 父级: ../CLAUDE.md

用户端模块，负责承载浏览器内的 SuperNote 产品体验边界。

技术栈: Bun + Vite + React 19 + React Router + Zustand + Motion for React (`motion/react`) + @xyflow/react 12 + react-archer 5.1 + Vercel AI SDK/useChat + @mastra/client-js + canvas-confetti + Kumo UI + Tailwind CSS v4 + 本地 design system + Supabase Auth SDK + system/light/dark 全局主题偏好 + Lucide React + CodeMirror 6/Lezer Markdown GFM + react-markdown/remark-gfm/remark-breaks/rehype-sanitize + TypeScript。

Canvas V2 已落地为一级持久 Workspace。memo 默认 Canvas 与 standalone Canvas 都直接进入同一 React Flow 会话；用户可添加已有 memo、预览/编辑原文、创建自由文字、连接/删除/拖拽/缩放，并显式触发 AI 增量拓展。所有 UI intent 先进入 IndexedDB WAL，再由单一保存协调器提交；页面重开、冲突、响应丢失和 pagehide 都沿同一恢复协议处理。旧 ExploreStage 生产路径与开发实验页已经移除。

交互组件约束: 侧栏导航必须复用 SidebarButton；文件库 Header 左侧保留紧凑 BrandMark，右侧只放 32px Ghost 收起图标；根级新建与搜索固定同排且整行 32px：搜索是中性 SidebarButton 占据弹性槽，只负责打开全局 Command Palette，文件库内不得再拥有本地输入框或独立搜索结果树；新建是右侧约 96px 的 Primary split 控件，64px 主区带图标与「新建」文字直接新建备忘录，32px 下拉区显式选择备忘录/Canvas/文件夹，两区共享同一 10px 平滑外轮廓并以 1px 低对比线分隔。这一行在搜索打开后不消失、不换成输入框、不发生布局跳动，也禁止扩张为整行实心长条。Design System 与回收站位于文件树之外的同一底部导航列表，各占一行、规格一致且不显示额外分组标题；二者复用 12px/16px Label 角色与 560 字重，只靠位置、16px 图标和状态色建立安静层级，禁止额外插入 13px 字号。标准 APP/设置动作与 Input/Select 使用 36px 高度，侧栏导航、文件树与 Header 命令使用 32px compact 高度，二者共享 smooth-corner、16px 图标和交互材质而不强制等高；递归文件树的 folder/memo 行通过 12px/16px 文字、字重、颜色与逐级缩进承载高频浏览密度，不绘制永久父子导轨。文件夹开合只允许 Folder/FolderOpen 单一状态图标，不额外添加 Caret；同层文件夹与文件共享固定图标槽，标题必须严格对齐。树行单击只负责导航或开合，双击任意 folder/memo、右键重命名或聚焦后 F2 均进入同一原地 input；Enter/blur 提交，Escape 取消。文件树节点是固定位置的扁平列表项，hover/press 不得产生位移或抬升。原生拖拽预览按节点身份分型：folder 必须显示纯文件夹图标与单行截断名称，memo 只显示纯 SVG 图标；二者都禁止胶囊、方框、按钮背景或实体阴影，仅允许图标/文字底层的极淡虚化光晕。拖拽源保留原位并弱化到 40%。拖拽命中区不得改变行高、层间距或整体高度；before/after/root-end 使用 8px 起始圆点+2px 插入线，folder 中段只显示原位放入态，实际位置变化统一用约 210ms Web Animations FLIP。除文件树的扁平交互例外外，其他 SidebarButton 的选中态和 prominent 态必须直接复用无明显描边 Secondary Button 的自然表面与内外阴影，不得维护第二套材质；Button、SidebarButton、UserButton 与 Select 的 hover/open 状态必须固定原位和静止深度，仅允许通过颜色或边框反馈，Button/SidebarButton 只有 press 可保留 1px 下压。UserButton、Select 动作和侧栏工具按钮同样消费统一平滑圆角，不得使用局部曲率。账户入口统一打开小尺寸 4:3 AccountDialog；192px 左栏不绘制重复的大标题栏，只以小型分组标题组织真实页面，当前“通用”只包含账户与外观，新增能力时再增加栏目或分组。每次打开只后台刷新一次真实 Profile，并继续展示 loader 或本地更新维护的旧资料；返回时仅合并未被用户修改的字段，禁止清空为 Skeleton，栏目切换不得重复请求。账户 username/bio 在停止输入 800ms 后静默自动保存并以 Toast 回执，不显示独立保存区或大按钮；模态框不得扩张为全屏设置页。瞬时业务反馈必须经根级 ToastProvider 发出，不在页面重复实现通知浮层。

图标系统约束: 通用图标统一从 `src/shared/design-system/icons.tsx` 取稳定语义别名，业务文件禁止直接引入第三方图标包。底层采用 Lucide React 的 24×24 网格、2px 描边、圆形端点与圆角连接，产品尺寸限制为 14/16/20/24px；Primary、选中态与状态反馈只改变 `currentColor` 或所在表面，不通过另一套 fill/duotone 图形制造视觉分裂。BrandMark、ThinkingMark、Archive Cord 与 Google 品牌标记属于明确的 Signature/品牌例外。DEV Design System 必须展示全部生产语义图标、导出名、真实用途和尺寸阶梯。

空间与尺寸约束: APP 以 4px 为唯一空间基线，并在 `src/index.css` 集中维护 32/36/48px 尺寸阶梯。三处 Panel Header 统一为 48px 高、12px 水平内边距；Header 图标命令、Sidebar 新建、中央阅读/更多/助手开关与关闭入口统一为 32px 容器和 16px 图标，因此上下自然各保留 8px 呼吸区，相邻命令间距统一为 4px。AI Header 只保留历史菜单、单行会话名、独立于 NotePencil 的 MessageCirclePlus 新对话和 PanelRightClose 尾端收起；关闭态 Stage 使用匹配的 PanelRightOpen，不展示品牌标记、副标题或权限胶囊。标准 Button、Input 与 Select 使用 36px 外部高度；Button 采用 14px/18px UI 字体、14px 水平留白与 6px 图文间距，表单采用 14px/20px。SidebarButton 与递归文件树行使用 32px compact 外部高度和 16px 图标，文件树和底部辅助导航均使用 12px/16px。认证表单可独立使用 48px 大点击规格。Agent Composer 使用 16px Panel 曲率和内层同心曲率，底栏只保留左侧权限与右侧发送/停止两个 32/16 Button；发送与停止共享 32px 几何圆形 Primary 轮廓，并以 `corner-shape: round` 显式覆盖通用 Button squircle，状态切换不得改变几何。原生 MentionInput 最多增长到 6 行后内部滚动，@候选是可滚动菜单内按内容宽度收束的 28px 文件图标+文件名单行，不得拉伸成整行 Button。首屏 Skeleton 必须使用相同尺寸 token，禁止加载跳变；DEV Design System 必须直接呈现这套空间标尺与 Header/Composer 样板，且不得复制另一套展示专用值。

备忘录状态约束: `src/shared/store/memoTreeStore.ts` 只保存 active 文件夹/笔记结构与摘要，`memoDocumentStore.ts` 是按 ID 正文与草稿的唯一客户端状态源；目录响应禁止携带 `content_mdx`，用户打开笔记后才读取该 ID 的完整正文并缓存，切换/登出必须中止或门禁旧响应。当前关键词搜索可由 `/memo-search` 在服务端匹配正文，但只回传命中 ID/摘要；未来向量/混合检索不得把正文重新塞回整树。GET 整树只允许在进入 Dashboard、登录用户变化或显式刷新时发生；人工创建必须同步插入临时 Memo、立即进入编辑器且不锁定后续创建，多个提交独立并发，临时/真实 ID 替换不得重挂载编辑器或覆盖等待期间的标题/正文，失败只精确撤销对应节点。重命名、移动、软删除与恢复同样必须乐观更新或合并局部响应，严禁写成功后刷新整棵树。Trash 只保存回收站列表视图状态，不得复制 active tree。删除当前 Memo 或其祖先前必须等待 `useMemoAutosave` required flush，失败保留路由、编辑会话和 subtree；删除成功后暂停旧会话、清理受影响 last-memo/正文缓存并导航到下一 Memo 或 `/app`。“需要 flush”与“需要导航离开”是两件事：画布没有编辑会话，删除正在打开的画布只导航不 flush，不得因为拿不到编辑器而静默失败。中央连续画布、Markdown、reading/live/source、安全渲染与空白保真继续遵循既有单一存储协议；自动保存仍使用既有调度/重试参数且所有保存携带显式 memoId。

命名约束: 重名的最终裁决在数据库唯一索引 `(user_id, parent_id, node_type, memo_title_norm(title))`（排除 deleted_at，根节点单独一条 partial index），前端 `shared/store/memoTitleRules.ts` 只是它的镜像，负责即时反馈。禁止同 user、同 parent、同 node_type、规范化标题相同；一篇笔记与它的默认 Canvas 同名、不同类型对象同名都合法。规范化只在两处各实现一次并保持同语义：首尾空白、连续空白折叠、拉丁大小写。系统生成的默认名（未命名备忘录 / 未命名 Canvas）撞名时由服务端顺位让开为「… 2」，用户亲手输入的名字撞名绝不替他改名，只回 409 `MEMO_TITLE_CONFLICT` 并原位提示。标题与正文是两条独立提交路径：撞名只挂起 title 字段并在标题编辑区原位提示（保持编辑态与用户输入、不发注定失败的标题请求、不静默回滚、也不把这个名字反写进文件树），正文必须继续正常自动保存；确定性冲突不进入退避重试。默认 Canvas 的名称等于来源笔记名且不含任何后缀，不可独立编辑——文件树的双击/F2/右键三个入口对它关闭，来源笔记改名时数据库触发器在同一事务内同步画布标题，客户端 Store 同步镜像这条事实以免文件树显示已被改掉的旧名。新建对象若在提交期间被服务端改名，本地以「是否还等于提交值」判定是否接纳，绝不用服务端返回值覆盖用户已开始输入的标题。

备忘录舞台约束: APP 使用纯中性灰 Workspace Stage 衬托唯一常驻 Paper；Light Paper 纯白、Dark Paper 为同一明暗轴上的深纸面，允许极弱边缘、克制圆角与多层柔影。写作态 Stage 禁止纹理、点阵、渐变光斑与任何空间/白板交互——Canvas Workspace 是唯一例外，其视觉不得反向渗透写作态。Paper 宽度上限 51rem、最小高度 `calc(100vh - 5rem)`，内部写作列上限 45rem；路径/Canvas/整理/阅读命令位于 Paper 顶部，文件库/AI 开关位于 Stage。切换 memo 只替换 Paper 内部内容；标题、正文、Panel 动画与 reading/live/source 切换不得破坏 CodeMirror 选区、撤销历史或自动保存会话。

知识画布约束: Canvas 是与 Paper 并列的一级持久 Workspace，树身份固定为 `memo_nodes.id === canvases.node_id`，memo 默认 Canvas 并发进入只能得到同一个 ID，standalone 从创建起也必须是 protocol 2。CanvasWorkspace 保持中央 React Flow 实例不因左右 Panel、Preview 或 Picker 开合而卸载；允许 pan/zoom、点阵、连接、删除、拖拽和自由文字四角等比缩放，空间文字静止时只显示文字，编辑态只有输入光标且无边框，选中才显示四边等距紧贴内容的四角边界；对象 `text_scale`（0.25–8）与宽高经同一 mutation 持久化，Canvas viewport zoom 只做视觉变换不改对象尺寸，`onlyRenderVisibleElements` 不开。恢复 user_moved 视口前必须先判定它在当前画布尺寸下还看得见节点，否则退回 fitView——视口是按存它时的设备算的，原样搬到更小的窗口会让整幅图落在屏幕外。memo_ref 卡片是固定 280x360 的纵向笔记预览纸：卡片只嵌一张共享 NotePaper thumbnail，只显示 snapshot 标题与摘录并在底部渐隐到固定高度元信息行，展开与上下文操作常驻 DOM 只靠透明度浮现，因此出现与消失都不改变布局；native 空间文字的宽高与 text_scale 是用户数据，卡片尺寸规则永不作用于它。整树读取给 canvas 节点附带画布身份（kind + origin_node_id），folder/memo 连键都不出现；两个画布入口把同一身份补回返回的 tree node，使就地并入目录的节点与整树一致，全局搜索靠它把默认画布去重成来源笔记行上的次级动作。memo_ref 只保存标题/摘要/revision 快照，正文只在用户打开 Preview 时按 memo ID 读取，Preview 是遮罩中央唯一出现的纸：几何是常量、不随正文长度变化，并按 ISO 216 的 1:√2 立成 A4 开本（宽取 40rem／视口高／视口宽三者最紧者，高由比例导出），以 --paper-float-shadow 的渐变柔影悬浮在明亮磨砂遮罩之上；页边固定为纸宽 8%。模态是固定取景框：纸面与纸外工具列在滚动中静止，正文在纸内滚动并复用全局细滚动条。纸内只允许正文，关闭与“编辑原文”一律住在与纸顶右角对齐的纸外 32px 圆形工具列（窄屏 44px），因此正文再长也不会把入口推出视野；Esc/遮罩/滚动锁定/焦点归还复用 Dialog bare 表面；从 Preview 编辑原文再返回时恢复 Canvas 路由、视口、选择和临时 Panel 状态。人工操作与 AI expansion 都必须生成同一 CanvasIntent，经 IndexedDB WAL 和 CanvasSaveCoordinator 进入唯一 mutation API；禁止组件直写第二条路径。协调器按 600ms 封装、100 操作/48KiB 上限、稳定 mutation_id、单次 409 rebase 和有界重试运行，pagehide 只 best-effort 发送首批且剩余 WAL 必须保留。AI 只在用户显式触发时运行，已有完整 checkpoint 且语料未变直接返回最新；新节点按既有分支向外增量布局，旧节点坐标永不因 AI 重排。Canvas 的全部非圆形表面必须与全站共享同一 squircle 平滑圆角，嵌套的卡片外壳与纸张只允许曲率半径不同、形状语言相同；圆形入口显式退回 round。Canvas 顶层只有四块分区，全部由 --canvas-chrome-inset/size/gap 一组变量定位并锚在 canvas-stage 上：左上是文件库开关+安静标题、右上是 AI 开关、底部中央是加入/适配/缩放/说明命令条、右下是保存状态；开关槽位常驻以保证标题横坐标不因面板开合而移动，禁止用零散 top/left 让浮层互相躲避，也不再有伪返回按钮、Canvas 文字标识或包裹整组内容的厚重卡片。标题是画布身份的唯一表达：默认 Canvas 的标题只读跟随来源笔记，点它等于带着返回描述回到原文；独立 Canvas 才能在此原地重命名。关系线复用 Cord Signature，理由与删除动作只在 hover/选中出现；文件树以图标区分 Canvas 与 memo，不暴露扩展名。reduced-motion 直接呈现静态终态。
