## 交互与路由

- 左侧四个原生按钮一次展开一项，正文保持挂载并通过 CSS grid 收放，收起时立即 inert；标题有 aria-expanded/aria-controls，当前项按单项展开模式声明 aria-disabled，仍保留键盘焦点；仅未展开项显示加号，展开项不显示无效的减号。
- 右侧实景图、顶部「了解更多」、展开项「了解更多」都随当前项切换；底部四个分栏是紧凑的标题/说明摘要，不含编号、文章元信息、阅读全文或链接。
- `detail` query 保存选中项；切换使用 replace、preventScrollReset，保留其他查询参数与 state，清除已消费的定位 hash，避免 Router 再次定位。未知值回到首项。不会把每次展开都塞进返回历史。
- 文章链接沿既有 `fromBlog` 来路协议。返回恢复相同展开项与滚动位置；直接进入文章则返回博客目录。未修改 BlogPage 的阅读/返回机制。
- 1440px 使用 5:7 展示与四列摘要；390px 展示上下排列，摘要双列。共享字体、墨蓝、按钮与细点阵背景延续现有 Landing。

## 排版精修

按用户反馈收紧三个层级：Header 保留 25.4px 主标题，说明使用 `--type-ui` 14px；展开标题使用 `--type-heading` 18px，正文与链接使用 `--type-label` 12px；底部标题/说明使用 14/12px。主标题继承其他区块的黑色 h2，细节标题为 foreground，说明与收起项统一为 muted-foreground。手机端保留同样的清楚层级。

展开项使用 flex 垂直居中整组标题、说明和链接，文字仍左对齐；桌面首项实测上/下空白为 76.5/77.5px。底部恢复原网格每格 24px × 48px 留白，四格只占一行、自然高度 114px，不保留原八格的两行总高度。删除编号、文章长标题、阅读全文和底部导航语义；文章继续从 Header 与展开项的「了解更多」进入。

精修通过 APP 类型检查与 lint；桌面实测字号为 25.4/14、18/12、14/12px，底部无链接。details-desktop.png 记录此前字号精修状态，早于图注、交互和标题颜色的后续修改。390px 实测字号层级正确、文档无横向溢出、文章返回保留选中项；手机截图工具超时，因此 details-mobile.png 和 details-mobile-guides.png 保留首轮历史画面，不代表此次精修结果。文章内容与产品图片不变。

## 展开跳动修复

复现发现两个独立原因：React Router 的 ScrollRestoration 先执行 hash 定位，随后才检查 preventScrollReset，因此带锚点切换 query 会重新滚到区块顶部；旧收起项的退出正文与新展开项同时参与自然高度，又会把 min-height 容器撑大。修复前桌面观测到 scrollY 从 5108 变为 4998，展示框从 456px 变为 546px。

切换现在清除已用于定位的 hash，并保留 detail/其他 query 与来路 state。展示区域明确拥有自己的高度：桌面 456px，手机展开区 420px、图片区 320px；四个分栏用固定收起基高与 flex-grow 共享剩余空间，以 DS tree 时长/曲线切换，正文通过 CSS grid 的 0fr/1fr 在各自格内收放，和标题字号/行高/内边距共享同一段过渡。图片区使用固定尺寸容器中的 object-fit:contain，不再由图片比例决定整框高度，也不裁掉图片内容。

桌面连续四项切换逐帧检查、390px 连续五次快速切换逐帧检查：scrollY、展示框高度、图片区顶部、底部摘要位置的变化均为 0px。手机只有一项展开，正文和文章入口未被裁切，居中文字上下空白均为 64.5px；进入文章并返回仍恢复 markdown 项。类型检查、lint 和生产构建通过。

随后逐帧定位到旧栏收起末尾的第二处抖动：正文卸载前仍占据上边距，卸载时标题回跳 6px。该处改为常驻正文的 grid 收放，内边距置于裁剪层内，标题统一字体族并对字号、行高与内边距连续插值，消除卸载后的二次重排。用户已确认交互流畅。区块主标题按用户反馈删除蓝色覆盖，直接继承与其他同级标题一致的黑色样式。

首页图片下方的重复图注已删除，博客正文图注仍保留。选中项的减号已删除，再点当前项无动作，点击另一项自动切换。

图片内容没有在此交互修复中替换：归档项仍复用功能网格真实图，其余三个为正式 UI 截图；原文预览图裁去了背景与空白，不能单靠此图展示进入前后的连续过程。四个细节主题未改变，现有取景对主题的表达不足应与 UI 真实性分开评价。
